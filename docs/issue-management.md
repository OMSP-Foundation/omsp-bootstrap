# OMSP Issue Management

## Issue Açma Kuralı

Her iş bir GitHub issue ile takip edilir.

Issue başlığı kısa ve eylem odaklı olmalıdır:

```txt
[Task]: Configure project auto-add workflow
[Feature]: Define bootstrap MVP scope
[Bug]: Fix failing CI job
```

## Issue İçeriği

Her issue şu yapıyı takip eder:

- Amaç
- Kapsam
- Kabul kriterleri
- Notlar

## Triage Kuralı

Yeni issue için:

1. Type belirlenir
2. Priority belirlenir
3. Area belirlenir
4. Sprint/milestone kararı verilir
5. Project status güncellenir

## Kapanış Kuralı

Issue sadece şu durumlarda kapatılır:

- Kabul kriterleri tamamlandı
- İlgili PR merge edildi
- İş artık yapılmayacaksa `not planned` olarak kapatıldı
